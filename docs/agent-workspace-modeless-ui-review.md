# モードレスUI設計レビュー: Agent Workspace

## 1. 対象と目的

- 対象画面・フロー: Macアプリの会話 → 仕様案の確認と修正 → HTMLプレビュー → 成果物確認。
- 主要ユーザー: ワイヤーフレームで仮説を確かめる企画・デザイン担当者。
- 主要オブジェクト: 会話、画面仕様案、生成HTML、実行結果。
- 達成したい目的: 仕様を見ながら会話とプレビューを行き来し、修正と再生成を途切れず進める。
- 成果物種別: 既存UIのレビューと、今回の変更を含む改善仕様。

## 6. 改善案

### P-01: 仕様を常設の作業対象にする

- 変更前: 仕様はシートに表示され、閉じるまで背景ペインを操作できない。
- 変更後: 右ペインの「仕様／成果物」インスペクタへ移す。仕様表示中も左の会話と中央のプレビューを操作できる。生成後も仕様を閉じず、結果は隣のタブで確認する。
- 守るべき振る舞い: 仕様確認を完了・キャンセルする前提をなくし、作業対象の切替だけで参照を続けられる。
- 採用理由: 仕様の判断には会話の文脈と生成プレビューが必要。
- トレードオフ: 仕様の横幅が狭くなる。スクロールと要約の情報設計が必要。
- 失敗時の復旧: 仕様JSONが読めない場合もインスペクタにエラーと詳細編集を残し、会話へ戻れる。
- 受入条件: 仕様を表示したまま会話入力、プレビュー操作、成果物表示の切替ができる。

### P-02: 修正対象から一操作で改訂案を作る

- 変更前: 修正指示を送った後、別の「仕様案を作る」操作が必要。
- 変更後: インスペクタの修正欄から「修正案を作る」でPiへ直接改訂を依頼する。元の仕様を表示したまま応答を待つ。
- 守るべき振る舞い: 修正指示は会話に残り、失敗しても元の仕様を消さない。
- 採用理由: 軽微で反復的な修正をタスクの中断にしない。
- トレードオフ: 中間の会話回答を見る工程を省くため、指示が曖昧な場合は改訂案を再修正する必要がある。
- 失敗時の復旧: 元の仕様を保持し、失敗内容を会話と状態表示に残す。
- 受入条件: 一度の操作で新しい仕様案が表示され、エラー時は旧版を確認できる。

### P-03: 前回プレビューを明確に識別する

- 変更前: 仕様を更新した後も前回生成したHTMLが中央に残り、新仕様に対応しているように見える。
- 変更後: HTML生成に使った仕様のスナップショットを保持し、現在仕様と異なる場合や生成中・失敗後は「前回の生成結果」と表示する。
- 守るべき振る舞い: 完了したプレビューを参照しながら作業できるが、その版を取り違えない。
- 採用理由: モードレスな並行表示では成果物の版を明示する必要がある。
- トレードオフ: 状態表示が増える。
- 失敗時の復旧: 旧プレビューを残し、仕様側から再生成できる。
- 受入条件: 仕様を変更した直後に旧プレビュー表示が明示され、新たな生成が成功すると解除される。

### P-04: モードレス化の次に必要な保存と中止

- 変更前: 会話・仕様は再起動で消え、進行中のPi・ビルドに中止操作がない。
- 変更後: 作業単位の自動保存、仕様版の復元、処理中の中止と再開を追加する。今回の変更では未実装。
- 守るべき振る舞い: ほかの作業へ移っても入力と成功済み成果を失わない。中止後の一時ファイルを完成品として扱わない。
- 採用理由: モードレスな作業継続をアプリ終了や長い処理にも広げるため。
- トレードオフ: ローカル保存とプロセス中断の整合性設計が必要。
- 失敗時の復旧: 最後の確定版を復元し、途中工程から再試行する。
- 受入条件: 再起動後の復元と、安全な処理中止が実機で確認できる。

### P-05: ワイヤーフレームを独立したプロジェクトとして並行管理する

- 変更前: 一つのウィンドウに会話・仕様・生成物が各1件。別仕様の読込は現在仕様を置き換え、処理中の結果を作業単位で分離しない。複数ウィンドウの状態はメモリ上に留まる。
- 変更後: **一つのウィンドウ内**で、ワイヤーフレームごとに安定したプロジェクトID、会話、仕様版、成果物、保存先、処理ジョブを持つ。左側にプロジェクト一覧を置き、「案を選ぶ → 会話する／仕様を直す／生成する」と操作する。生成中の案を離れて別案を編集でき、完了は元の案へ届く。仕様ファイルの読込は新規案として追加する。
- 守るべき振る舞い: 切替後も各案の入力と進捗を保持し、非同期の結果は開始時のプロジェクトIDと仕様版が一致する対象にだけ反映する。
- 採用理由: ウィンドウやインスペクタをモードレスにしても、対象オブジェクトが一件だけなら複数案件の並行作業は成立しない。
- トレードオフ: プロジェクト保存、ジョブ所有、結果の競合と通知の設計が必要。
- 失敗時の復旧: 失敗は対象案の履歴に残し、ほかの案の作業を止めない。アプリ再起動後も各案の最終確定状態を復元する。
- 受入条件: 同じウィンドウでAの生成中にBを編集・生成し、Aの完了後も両方の会話・仕様・成果物が混ざらない。再起動後に同じウィンドウの一覧からAとBを選び直せる。

### P-06: モデルへの接続と選択をアプリ内に置く

- 変更前: モデルIDを直接入力し、認証はターミナルのPiで設定する。
- 変更後: 左のプロバイダー一覧でOpenAI CodexまたはAnthropicを接続する。ブラウザーを開いた後も案件を操作でき、確認コードが必要なら左ペインへ入力する。接続済みプロバイダーの利用可能モデルだけを案件の一覧に表示する。
- 守るべき振る舞い: 認証中も案件を切り替えられる。資格情報を案件の保存データや画面へ表示しない。未接続や無効なモデルでは送信しない。
- 採用理由: 利用者の対象はモデルと案件であり、ターミナルやモデルID文字列ではない。
- トレードオフ: 認証中に外部ブラウザーは開く。プロバイダーが手動コード入力を求める場合はアプリ内の入力が必要。
- 失敗時の復旧: エラーを接続欄に残し、接続を再試行できる。認証中止後も案件データを保持する。
- 受入条件: ターミナルを使わずに各プロバイダーへ接続し、提供モデルを一覧から選択できる。認証中も別案件を操作できる。

### P-07: ログアウト時に対象手順を即時停止する

- 変更前: プロバイダーをアプリからログアウトできず、生成中の案件は認証状態と独立して進む。
- 変更後: プロバイダー欄に「ログアウト」を置く。押した時点でそのプロバイダーのモデルを利用不可にし、対象案件の実行中ジョブを中断する。資格情報の削除を非同期で進める間も、閲覧・編集・他プロバイダーの案件は操作できる。
- 守るべき振る舞い: ログアウト後の遅着結果で会話、仕様、成果物を進めない。再ログインまで送信、改訂案の適用、生成、再試行を禁止する。中断状態と入力は保持する。
- 採用理由: ログアウトは利用者がモデルの利用許可を取り消す操作であり、表示だけ切り替えて実行を続けると意図に反する。
- トレードオフ: 中断した生成は自動再開しない。再ログイン後の再試行を利用者が選ぶ。
- 失敗時の復旧: SDK側の削除に失敗してもアプリ内の停止を維持し、エラーと再接続の入口を残す。成功済み成果物は消さない。
- 受入条件: Aで生成中に対象プロバイダーからログアウトするとAが中断になり、遅着結果は反映されない。再ログイン前はAを進められず、再ログイン後に再試行できる。別プロバイダーのBは継続できる。

## 7. 状態と例外

| 状態 | 表示 | 可能な操作 | 禁止する操作 | 復旧手段 |
|---|---|---|---|---|
| 初期 | 会話の問い、空のプレビュー、成果物。仕様タブには空状態 | 会話、仕様ファイル読込、保存先選択 | 仕様なしの生成 | 会話またはファイルから開始 |
| 仕様編集中 | 右に仕様案、中央に現行または旧プレビュー | 会話、詳細編集、修正案作成、生成 | 不正仕様の生成 | 該当欄を修正 |
| Pi処理中 | 会話の進捗と仕様欄の改訂中表示 | 旧仕様とプレビューの参照 | 重複Pi送信、生成 | 完了待ち。中止は未実装 |
| 生成中 | 中央の進捗、旧プレビューの版表示 | 会話と仕様の参照 | 重複生成 | 成功か失敗の表示を待つ。中止は未実装 |
| 成功 | 構造チェック合格、保存ファイル、現仕様に対応するプレビュー | 確認、再編集、Finder表示 | なし | 新版を生成 |
| 失敗 | 成果物ペインに失敗状態とログ、旧プレビューに版表示 | 仕様修正、再試行、ログ確認 | 失敗したHTMLの完成品扱い | 元仕様を残して修正または再試行 |
| オフライン・権限不足・競合・部分完了 | 現MVPでは独立した状態として未実装 | 既存のローカル成果物参照 | 成功扱い | 状態分類と復旧UIを今後設計 |
| 複数案の並行作業 | 現MVPでは一つのウィンドウ内にプロジェクト一覧と作業IDがない | 別案への安全な切替はできない | 別案を現仕様へ上書きすること | ウィンドウ内の一覧とプロジェクト別の状態・ジョブ管理を追加 |
| プロバイダー未接続 | 接続状態と接続ボタン、モデル未選択案内 | 案件閲覧・編集、接続開始 | モデルへの送信 | 接続してモデルを選ぶ |
| 認証中 | 接続進捗、ブラウザーへのリンク、必要なら確認コード入力、中止 | 別案件の閲覧・編集 | 同じ接続処理の重複開始 | 完了、コード入力、中止 |
| 認証失敗 | 接続欄に持続するエラー | 案件閲覧・編集、再接続 | 未接続モデルへの送信 | 再接続 |
| ログアウト済み | 案件内に一時停止の説明、プロバイダー欄に接続入口 | 閲覧・編集、他プロバイダーの作業、再ログイン | 対象モデルでの送信、改訂案適用、生成、再試行 | 再ログイン後に手動で再試行 |
| ログアウト処理失敗 | 接続欄に持続するエラーと停止状態 | 閲覧・編集、再接続 | 対象モデルの利用 | アプリ内で再ログイン |

## 8. モーダルを残す根拠

| 操作 | 拘束が必要な理由 | 閉じ方 | キャンセル時の扱い | フォーカスの戻り先 |
|---|---|---|---|---|
| OS標準の仕様ファイル選択 | 選択対象と権限を一度に確定する独立操作 | 選択またはキャンセル | 現在の仕様を維持 | 「仕様ファイルを開く」ボタン |
| OS標準の保存先選択 | 書き込み先を明示的に選ぶ独立操作 | 選択またはキャンセル | 現在の保存先を維持 | 「保存先」ボタン |

将来の公開・他者への送信は不可逆な影響があるため、具体的な対象と内容を示す直前確認を検討する。現MVPに公開・共有機能はない。
