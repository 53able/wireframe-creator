# Agent Workspace 複数プロジェクト実装タスクリスト

## 目的

一つのMacアプリウィンドウ内で、複数のワイヤーフレームを独立したプロジェクトとして扱えるようにする。プロジェクトAのPi応答またはHTML生成を待ちながら、プロジェクトBへ切り替えて会話・仕様編集・生成を進められることを完成条件とする。

## スコープ

- 各プロジェクトに安定したID、名前、会話、入力途中の文章、モデルID、仕様JSON、仕様版、保存先、生成物、実行状態、ログを持たせる。
- 一ウィンドウ内にプロジェクト一覧と選択状態を置き、選択中プロジェクトの会話・プレビュー・インスペクタを表示する。
- Pi処理とHTML生成をプロジェクト単位で所有し、異なるプロジェクトのジョブを同時に実行できるようにする。
- プロジェクトと確定済みの作業状態をローカルへ自動保存し、アプリ再起動後に復元する。
- 仕様ファイルの読込は新規プロジェクトの作成として扱う。既存プロジェクトの置換はこのMVPに含めない。

## スコープ外

- 複数ウィンドウによる並行管理。
- クラウド同期、共同編集、プロジェクト共有。
- 実行中プロセスそのものの再起動後の継続。再起動時は中断状態として復元し、再試行できるようにする。
- プロジェクト削除、アーカイブ、並べ替え、検索などの管理機能。
- Pi・Node・Pythonプロセスのキャンセル機能。

## 実装上の不変条件

1. 非同期結果は、ジョブ開始時のプロジェクトIDと仕様版が一致する対象にだけ反映する。
2. 選択中プロジェクトが変わっても、完了したジョブの結果を現在表示中の別プロジェクトへ書き込まない。
3. 保存するのは確定済み状態であり、実行中ジョブは再起動後に「中断」に変換する。
4. プロジェクト切替はモードレスで、処理完了や確認操作を要求しない。
5. 同一プロジェクト内では、Piジョブを一件、ビルドジョブを一件までとする。別プロジェクトのジョブは互いにブロックしない。

## 実装タスク

### [ ] T-01 プロジェクト状態と保存形式を定義する

対象: `Sources/AgentWorkspace/WorkspaceModel.swift`、必要に応じて新規のプロジェクトモデル／ストアファイル。

- 現在グローバルに保持している会話、入力、モデルID、仕様、保存先、生成物、状態、ログを`projectID`配下へ移す。
- `projectID`は生成後に変わらないUUIDとし、表示名とは分離する。
- 仕様変更ごとに単調増加する`specRevision`を持たせる。
- Pi・ビルドの状態を、未実行／実行中／成功／失敗／中断としてプロジェクト別に表現する。
- 永続化対象と一時的な実行オブジェクトを分離する。`Task`や`Process`は保存形式に含めない。

受入条件:

- AとBが異なるIDと完全に分離された会話、仕様、生成物、ログ、保存先を持つ。
- Aの値を更新してもBの値が変わらない。
- 仕様を編集すると、そのプロジェクトだけの`specRevision`が更新される。
- 保存データに実行中の`Task`や`Process`を直列化しない。

### [ ] T-02 プロジェクトストアと自動保存・復元を実装する

対象: `Sources/AgentWorkspace/WorkspaceModel.swift`、必要に応じて新規の永続化ストアファイル。

- Application Support配下にプロジェクト一覧と選択中IDを原子的に保存する。
- 新規起動時は既定プロジェクトを一件作成し、既存データがあれば全プロジェクトと最後の選択を復元する。
- 会話、入力途中の文章、仕様、仕様版、生成物参照、ログ、モデルID、保存先の変更を自動保存する。
- 壊れた保存データではアプリ全体を起動不能にせず、復旧可能なエラー状態を表示する。
- 再起動時に保存上「実行中」だったジョブは「中断」へ変換し、既存の確定仕様と成功済み生成物を維持する。

受入条件:

- AとBを作成して異なる会話・仕様・入力途中文章を設定し、アプリ再起動後に両方を選び直せる。
- 最後に選択していたプロジェクトが再起動後に選択される。
- 成功済み成果物への参照とログが再起動後も表示される。
- 実行途中で終了したプロジェクトは成功扱いにならず、「中断」と再試行導線を表示する。
- 保存失敗または破損を、他プロジェクトのデータを消去せずユーザーへ通知する。

### [ ] T-03 一ウィンドウ内のモードレスなプロジェクト選択を実装する

対象: `Sources/AgentWorkspace/AgentWorkspaceApp.swift`。

- 左端に常設のプロジェクト一覧を追加し、選択中のプロジェクト名、処理中、失敗、未保存エラーを判別できる状態表示を付ける。
- 「新規プロジェクト」を一覧内から実行できるようにする。
- プロジェクトを選ぶと、会話、入力欄、プレビュー、仕様／成果物インスペクタをそのプロジェクトへ一括で切り替える。
- 切替時に確認ダイアログを出さず、入力途中文章を保持する。
- 仕様ファイルを開いた場合は新規プロジェクトとして一覧へ追加し、そのプロジェクトを選択する。

受入条件:

- 同じウィンドウでAとBを一覧から即時に切り替えられる。
- Aで入力途中の文章を残してBへ移り、Aへ戻ると入力が復元される。
- Aの仕様、プレビュー、ログを表示中にBを選ぶと、四領域すべてがBへ切り替わり、Aの内容が混在しない。
- Piまたはビルド実行中のプロジェクトから離れても、一覧上で処理中と分かる。
- 仕様ファイル読込で既存プロジェクトを暗黙に上書きしない。

### [ ] T-04 Piジョブをプロジェクト単位で並行実行する

対象: `Sources/AgentWorkspace/WorkspaceModel.swift`、`Sources/AgentWorkspace/PiChatService.swift`。

- `sendMessage`、`proposeDraft`、`reviseDraft`の開始時に、対象`projectID`、ジョブID、開始時の`specRevision`、会話スナップショットを固定する。
- 全体の`isResponding`を廃止し、プロジェクト別のPi実行状態でボタン可否と進捗を制御する。
- 完了時は開始元のプロジェクトへ結果を配送する。選択中プロジェクトを参照して配送先を決めない。
- 仕様案・改訂案は開始時の仕様版が現在版と一致するときだけ採用する。不一致時は自動上書きせず競合として保持する。
- AのPi処理中でもBのPi処理を開始できる。

受入条件:

- AのPi応答待ちにBへ切り替え、Bで会話送信または仕様案作成を開始できる。
- Bを表示中にAの応答が完了しても、応答はAの会話と状態だけへ追加される。
- AとBのPiジョブが同時に動いても、ボタン無効化と進捗表示は各プロジェクトだけに適用される。
- ジョブ開始後に同じプロジェクトの仕様版が変わった場合、古い改訂結果で新しい仕様を上書きしない。
- 失敗は開始元プロジェクトに残り、他プロジェクトの操作を止めない。

### [ ] T-05 ビルドジョブと成果物をプロジェクト・仕様版へ結び付ける

対象: `Sources/AgentWorkspace/WorkspaceModel.swift`、`Sources/AgentWorkspace/BuildService.swift`。

- ビルド開始時に`projectID`、ジョブID、仕様JSON、`specRevision`、保存先、ファイル名を固定する。
- 全体の`isBuilding`を廃止し、プロジェクト別のビルド状態を管理する。
- 成功・失敗・ログ・成果物URLを開始元プロジェクトへ配送する。
- 成果物に生成元の`specRevision`を記録し、現行仕様との差を「前回の生成結果」として判定する。
- 異なるプロジェクトで同時に生成しても、一時ファイルと正本ファイルが衝突しない状態を維持する。

受入条件:

- Aの生成中にBを編集し、Bの生成も開始できる。
- Bを表示中にAの生成が完了しても、Aのプレビュー、成果物URL、ログだけが更新される。
- AとBの成果物ファイルが別々に保存され、Finder表示が正しい対象を開く。
- 生成中に元プロジェクトの仕様が変わった場合、完成物を現行版として誤表示せず旧版として残す。
- Aの生成失敗がBの生成状態、成果物、再試行操作へ影響しない。

### [ ] T-06 プロジェクト別通知・失敗復旧と統合動作を仕上げる

対象: `Sources/AgentWorkspace/AgentWorkspaceApp.swift`、`Sources/AgentWorkspace/WorkspaceModel.swift`。

- 非選択プロジェクトのジョブ完了・失敗を一覧上の持続する状態として表示する。
- プロジェクト選択後、そのプロジェクトの失敗内容、ログ、再試行操作を表示する。
- 再試行は失敗したプロジェクトと固定された仕様版を対象にする。
- 選択切替によってフォーカスが失われても、入力内容とスクロール対象をプロジェクト単位で保つ。
- キーボードでプロジェクト一覧へ移動し、選択できるラベルとフォーカス順を付ける。専門的なアクセシビリティ適合は別途検証する。

受入条件:

- Aを生成中のままBで会話、仕様編集、生成を完了できる。
- Aの完了または失敗が一覧で分かり、Aへ戻ると対応する結果と復旧操作が表示される。
- AとBを交互に操作しても、会話、仕様、入力、成果物、ログ、進捗が混ざらない。
- AとBを保持したまま再起動し、両方の最終確定状態を復元して作業を再開できる。
- 一方の保存・Pi・ビルド失敗が、もう一方の閲覧と編集を妨げない。

## QAゲート

各タスクは受入条件を満たす証拠が得られるまで次へ進めない。最大三回の修正ループを行い、同じ失敗が続く場合は阻害要因と再現手順を記録する。

最終統合では、少なくとも次の一連の操作を確認する。

1. 新規プロジェクトAとBを一つのウィンドウ内で作成する。
2. Aで会話と仕様案を作り、PiまたはHTML生成を開始する。
3. Aの処理中にBへ切り替え、会話、仕様編集、HTML生成を行う。
4. AとBの完了順を変えても、各結果が開始元だけへ届くことを確認する。
5. Aの仕様を生成中に変更し、旧仕様の成果物が現行版として扱われないことを確認する。
6. アプリを再起動し、AとBの会話、入力、仕様、成果物、ログ、選択状態を確認する。
7. Pi失敗、ビルド失敗、保存データ破損を個別に発生させ、他プロジェクトが操作可能なことを確認する。

## 完了条件

- T-01からT-06までの受入条件がすべて満たされている。
- 一ウィンドウ内で、Aの処理中にBを編集・生成できる。
- 非同期結果が別プロジェクトまたは別仕様版へ混入しない。
- 再起動後に複数プロジェクトの最終確定状態を復元できる。
- 実行中断、失敗、競合、保存エラーが成功として表示されず、対象プロジェクトから復旧できる。

## 実装前に確定したMVP判断

- 新規仕様ファイルは常に新規プロジェクトとして読み込む。
- プロジェクト名は新規作成時の既定名または仕様タイトル／ファイル名から設定する。名称編集は必須範囲に含めない。
- 成功済みHTMLは既存の出力先へ保持し、プロジェクト保存データにはURLと生成元仕様版を記録する。
- アプリ終了時の実行中ジョブは再開せず、中断状態から明示的に再試行する。
