# 規定ブラウザ接続プロトコル

プレビューサーバーを使う場合とブラウザ検証を行う場合に読む。目的は、OSの既定ブラウザではなく、実行環境がエージェント操作用として規定したブラウザで同じプレビューURLを開くことである。

## 1. 規定ブラウザの決定

次の優先順で、使用するブラウザを1つだけ決める。

1. 利用者が今回の依頼で明示したブラウザ
2. プロジェクトの `AGENTS.md`、`CLAUDE.md`、または同等の実行規則が指定したブラウザ
3. 実行環境で可視なブラウザ用スキルが `default`、`prefer`、または同等の既定指定をしているブラウザ
4. 実行環境が提供する標準の可視ブラウザ自動化ツール

選択したブラウザ用スキルまたはツールの説明を読み、その正規の起動・接続方法を使う。特定製品名、実行ファイルパス、macOS・Windows・Linux固有コマンドをこのスキル側で固定しない。

`open`、`start`、`xdg-open`、Pythonの `webbrowser` など、OSの関連付けへ委ねる方法は使わない。これらは実行環境が規定したブラウザを保証できない。

同順位の候補が複数あり、環境規則から一意に決められない場合は、勝手に併用せず、ブラウザ検証を `not run（規定ブラウザを一意に決定できない）` とする。利用者がブラウザでの表示自体を主目的としている場合だけ、1件の確認質問を行う。

## 2. プレビューサーバーへの接続

1. `serve-preview.py` を起動し、標準出力から `PREVIEW_URL` を取得する。
2. 規定ブラウザのナビゲーションAPIへ `PREVIEW_URL` を渡して開く。URLを表示するだけ、またはOSへ委譲しただけで接続済みとしない。
3. ブラウザが示す現在URLまたはページ状態を取得し、`PREVIEW_URL` と同じlocalhostのホスト・ポートへ接続したことを確認する。
4. 作業中は同じブラウザセッション、TaskSpace、context、または同等の単位を再利用する。更新確認のたびに別ブラウザを起動しない。
5. 接続後に、進捗UIまたはワイヤーフレームのタイトルが表示されることを確認する。確認できない場合は接続を `fail` とし、HTML生成や構造検証の成功と混同しない。

## 3. 最終化後の静的HTML引継ぎ

最終化後は、プレビューサーバーを停止する前に、利用者が見ている同じ規定ブラウザの現在のプレビュータブを正本HTMLの `file://` URLへ移す。HTTPページから `file://` へのクリック可能なリンクはChromium系ブラウザで拒否されるため生成しない。代わりに、最終化のホットリロード後は `[data-static-html-handoff]` 内へ、同一オリジンから完成HTMLを保存できるリンクを表示する。新しいタブだけを開いてlocalhostの旧タブを残す方法は、表示の連続性を保証しないため引継ぎ成功としない。

正本HTMLのURLは手作業で連結せず、絶対パスから実行環境のパスAPIで生成する。Pythonを使える場合は次の方法で、空白、日本語、`#` などを含むパスを正しくエンコードする。

```bash
STATIC_URL="$(python3 -c 'from pathlib import Path; import sys; print(Path(sys.argv[1]).resolve().as_uri())' "$CANONICAL_HTML")"
```

引継ぎは次の順序で行う。

1. 生成と検証の完了時刻から `CANONICAL_HTML` を決定し、`set-output`、`finalize --output`、`verify-final` を完了する。開始時刻をファイル名へ使わない。
2. 現在のプレビュータブで `[data-static-html-handoff] [data-static-html-link]` が表示され、リンクが同一オリジンの `/__wireframe/static` を指し、`download` 属性の値が完了時刻付き正本ファイル名であることを確認する。可能ならダウンロードを1回実行し、完成HTMLであることを確認する。
3. 引継ぎヘッダーの `data-static-html-url` が `STATIC_URL` と一致することを確認する。この値をページ内リンクとしてクリックしない。
4. 規定ブラウザのナビゲーションAPIへ `STATIC_URL` を直接渡し、現在のプレビュータブを再ナビゲーションする。
5. ブラウザが示す現在URLが `STATIC_URL` と一致し、タイトルと `[data-wireframe-root]` が表示されたことを確認する。
6. 開始画面から主要タスクの完了状態まで操作し、正本HTML内の通常ランタイムが動作することを確認する。
7. ここまで成功した後だけ、`preview-process-lifecycle.md` に従ってプレビューサーバーを停止・回収し、生存していないこと、zombie/defunct状態でないこと、URLが応答しないことを確認する。
8. サーバー停止後も現在URLが `file://` のままで、画面が表示されていることを確認する。

作業中DOMの残存状態だけを根拠に最終版を検証済みとしない。現在URL、主要画面、操作結果、サーバー停止後の表示状態を記録する。ブラウザ用スキルがスクリーンショットやスナップショットを提供する場合は、必要な検証範囲に限って利用する。

## 4. 利用不能時

規定ブラウザを起動できない、接続できない、操作権限がない、または `file://` ナビゲーションが許可されていない場合は、別のブラウザへ無断でフォールバックしない。次を行う。

- 構造検証は続行する。
- ブラウザ検証と静的HTML引継ぎを `not run` または `fail` とし、具体的な理由を記録する。
- 作業中にプレビューサーバーを起動していなければ、新たに起動しない。
- 起動済みプレビューから静的HTMLへ引き継げない場合は、利用者の表示を切断しないためサーバーを停止せず `intentional-handoff` とし、残存URLとPIDまたはhandleを報告する。
- 「静的HTMLへ切り替えた」「サーバー停止後も表示を確認した」「操作検証済み」と報告しない。

代替ブラウザの利用が実行環境の規則で明示的に許可されている場合だけ、その規則に従って切り替え、使用したブラウザと理由を報告する。
