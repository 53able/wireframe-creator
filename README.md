# wireframe-creator

プロジェクト要件から検証目的を定義し、操作可能な低忠実度HTMLワイヤーフレームを生成・検証する Agent Skill です。

## 特徴

- 外部依存のない単一HTMLを生成
- Pico CSS v2.1.1をインライン化したセマンティックなHTML
- 主要ユーザーフロー、状態、前提、未解決事項を明示
- 構造検証用のPythonスクリプトを同梱
- localhost限定のプレビューと作業中のホットリロードに対応
- 作業開始直後に進捗プレビューを開き、生成・検証状況を可視化
- 完了時刻付きの正本HTMLを生成し、静的HTMLの保存とブラウザ引継ぎを検証
- 新規作成、壁打ち、既存ワイヤーフレームの段階的改稿に対応

## インストール

[`skills`](https://github.com/vercel-labs/skills) CLIを使用します。

```bash
npx skills add 53able/wireframe-creator
```

特定のエージェントへグローバルインストールする場合:

```bash
npx skills add 53able/wireframe-creator -g -a claude-code -y
```

利用可能なスキルとして認識されるかだけを確認する場合:

```bash
npx skills add 53able/wireframe-creator --list
```

## 必要環境

- Python 3.10以上
- 完全な視覚検証を行う場合は、レンダリング済みページを操作できるブラウザ自動化ツール

Pythonスクリプトは標準ライブラリだけを使用します。

## Macワークスペース（MVP第1スライス）

SwiftUIアプリでAIモデルと会話し、画面仕様案を確認してから、Markoビルド、構造検証、検証済みHTMLの保存、WKWebViewプレビューまで実行できます。開発にはmacOS 14以降、Swift 6.2以降、Node.js 20.19以上の20系または22.12以上、Python 3が必要です。

左下の「モデルプロバイダー」からOpenAI CodexまたはAnthropicを接続します。アプリがブラウザーの認証ページを開き、必要な確認コードは同じウィンドウに入力できます。接続後、案件の「モデルを選択」から、そのプロバイダーの利用可能なモデルを一覧で選びます。モデルIDの入力やターミナル操作は不要です。認証情報はPi SDKの保存領域で管理し、案件データには含めません。[Piの認証案内](https://pi.dev/docs/latest/providers)、[Piのモデル一覧の仕組み](https://pi.dev/docs/latest/models)

同じ欄の「ログアウト」で、そのプロバイダーを使う案件の進行を即時に停止します。実行中の会話・仕様案・HTML生成は中断として残し、遅れて届いた結果を反映しません。会話や仕様の閲覧と編集は続けられますが、送信、改訂案の適用、HTML生成、再試行は再ログインしてモデルが使えるまで無効です。別の接続済みプロバイダーを使う案件には影響しません。中断した処理は再ログイン後に手動で再試行します。

```bash
npm ci
scripts/run-mac-workspace.sh
```

左側の「＋」で既定名の新しい案をすぐ作れます。隣の鉛筆ボタンから名前を付けて作成することもできます。各案件の「…」から名前の変更やアーカイブができ、アーカイブ欄から復帰できます。アーカイブ中の生成は中断され、復帰後に必要なら手動で再試行します。仕様ファイルは新規案件として読み込めます。案件を選び、チャットで検証したい流れを伝えて「仕様案を作る」を選びます。右側の「仕様」インスペクタには対象ユーザー、検証目的、画面と操作の流れ、判断してほしい点を日本語で表示します。会話とプレビューを見ながら確認でき、修正点は「修正案を作る」から一度に改訂できます。内容がよければ「この内容でプレビューを作る」を選びます。JSONの直接編集は「詳細データを表示・編集」にあります。右側の「成果物」へ切り替えると保存先と実行ログを確認できます。保存先は既定で`dist/`、アプリの「保存先」から変更できます。生成と正本の両方が構造検証に合格した場合だけ、完了時刻付きHTMLを保存・表示します。通常の会話ではPiのツールを無効にしています。チャット欄で`/`を入力すると`~/.agents/skills`にあるスキルを補完でき、選択後に依頼文を続けて送信できます。スキル実行時は選択したスキルだけをPiに読み込みます。スキル自身の参照ファイルは読み取れます。それ以外のファイル操作やシェル操作が必要になると、操作内容を案件内に表示して一件ずつ許可を求めます。作業ディレクトリは案件の保存先ですが、アクセス範囲の制限ではありません。スキル実行結果と操作概要は会話へ戻り、必要なら同じ依頼を再試行できます。Piの標準ツール以外の専用機能を要求するスキルは、その部分を実行できません。

日記本文などの複数行入力には`textarea`を使えます。AIが入力形式を省略した場合は、本文・内容・メモなどの欄を複数行、それ以外を1行として補います。仕様インスペクタには補ったことを表示します。生成に失敗した場合は、右側の「成果物」にある「同じ仕様で再試行」からAIを呼び直さずに再実行できます。仕様案はツールバーの「仕様を確認」から再表示できます。仕様を変更した後も前回のプレビューを参照できますが、新しい仕様とは異なる旨を表示します。生成HTMLで動くのは画面遷移と入力値の表示で、本文切替や保存処理は含まれません。

案件ごとの会話、入力途中の文章、仕様、成果物への参照はローカルへ自動保存します。ある案件のPi応答やHTML生成を待ちながら別案件へ切り替えて作業でき、結果は開始元の案件に戻ります。アプリ終了時に実行中だった処理は再開されず、次回は中断として表示されます。既存HTMLのJSON移行とアプリ終了後の処理継続は未実装です。アプリは開発用の未署名ビルドで、`scripts/run-mac-workspace.sh`が`dist/Agent Workspace.app`を作ります。

チャットの「画像を添付」へFinderの画像をドロップするか、「ファイルを選択」から追加できます。送信前にサムネイルを確認・削除でき、送信した画像は会話にも残ります。`/スキル名`の依頼にも画像を一緒に渡せます。画像は案件ごとにApplication Supportへコピーされ、元ファイルを移動しても再試行できます。1枚20MB以下、送信前は8枚までです。画像入力に対応したモデルを選んでください。

チャット入力欄は複数行を表示し、長文は欄内でスクロールできます。Enterで送信、Shift+Enterで改行します。日本語入力の変換中はEnterで送信しません。

v0.0.4では、仕様に宣言した操作と画面上の操作を照合し、「動作する／画面遷移のみ／表示のみ／未対応」を生成前の仕様確認とHTMLプレビューに表示します。判定はビルダーが実際の画面遷移と入力値反映を基に作り、HTML内の表示との一致を構造検証で確かめます。語り口による本文差し替えや保存処理など、ランタイムにない動作は実行されず、その範囲を明示します。旧仕様は引き続き生成できますが、自由文に書いた動作は自動照合の対象外です。

### Macアプリのパッケージ

```bash
scripts/package-mac-workspace.sh
```

`dist/Agent-Workspace-0.0.4-<CPU>.dmg`に、アプリ本体、モデル実行コンポーネント、Node.js、Marko・Tailwind CSSの生成資材を収めます。DMG内のアプリをApplicationsへコピーして起動できます。HTMLの初期保存先は「書類/Agent Workspace」です。HTML生成の構造検証にはPython 3が必要です。署名はアドホックで、Appleの公証は未実施です。開発用スクリプトは引き続きリポジトリを指定して起動します。`gray`・`grey`の配色指定はグレー系の`slate`として扱います。

## Marko + Tailwind CSS の新規生成器

画面データをJSONで編集し、Marko 6とTailwind CSS 4で単一HTMLへ変換する生成器を追加しています。Node.js 20.19以上の20系または22.12以上と`npm ci`が必要です。生成後は既存の構造検証器で確認できます。

```bash
npm ci
node builder/build-wireframe.mjs examples/wireframe.json dist/wireframe.html
python3 scripts/validate-wireframe.py dist/wireframe.html --min-screens 2 --require-actions
```

現在の`SKILL.md`に沿う進捗表示・最終化経路はPico CSSを使用します。MacアプリはMarko生成物を独立した経路で保存します。構成と移行順序は[`docs/agent-workspace-architecture.md`](docs/agent-workspace-architecture.md)を参照してください。

## Pico CSS

生成HTMLのスタイル基盤にはPico CSS v2.1.1を使用します。`assets/pico.manifest.json`でバージョン、取得元、CSSとライセンスのSHA-256を固定し、`scripts/render-wireframe-template.py`と進捗初期化処理が検証済みCSSをHTMLへインライン化します。CDNや実行時のネットワーク接続は使いません。

単体で保存・配布されるHTMLごとにライセンス条件を満たすため、Pico CSSの著作権表示とMITライセンス全文も`style[data-pico-css]`へ埋め込みます。原文は`assets/pico.LICENSE.md`、取得元は[Pico CSS v2.1.1](https://github.com/picocss/pico/releases/tag/v2.1.1)です。

固定版の更新と既存HTMLの明示的な移行手順は[`references/pico-css.md`](references/pico-css.md)に記載しています。
